# Pinned Python dependencies for the AAT poster renderer.
#
# Installed with `pip install --require-hashes -r requirements.txt`, which pip only accepts if
# EVERY requirement — direct and transitive — is pinned to an exact version with hashes. That is
# why packages nobody imports directly (contourpy, kiwisolver, six, ...) are listed: leaving one
# unpinned would disable hash checking for the whole file.
#
# WHY THESE VERSIONS
# ------------------
# matplotlib 3.11.1 and numpy 2.5.1 are what /home/user/AAT/uv.lock resolves for Python >= 3.12,
# i.e. exactly what the desktop application uses to write `results_AAT/graphs/*.png`. That is the
# entire reason a poster rendered here is comparable with one exported there.
#
# Pillow is not incidental either: since Matplotlib 3.3, `savefig(format="png")` encodes the PNG
# through Pillow, so Pillow's version participates in the byte-level output. FreeType is not
# listed because it is not a PyPI package — it is compiled into the Matplotlib wheel, which means
# pinning Matplotlib pins the glyph rasteriser too, and no system font package is needed.
#
# EVERY LINE IN THIS FILE IS PART OF THE VISUAL CONTRACT. Changing one may move pixels. See
# README.md and docs/supply-chain.md: poster-renderer updates never auto-merge.
#
# PLATFORM COVERAGE
# -----------------
# PYTHON 3.12 OR NEWER IS REQUIRED: numpy 2.5.1 publishes no cp311 wheels and declares
# `requires_python >= 3.12`, so a CI runner whose `python3` is older cannot install this file at
# all. That is a property of the pinned NumPy, not of this list.
#
# Hashes cover linux x86_64 and aarch64 wheels for CPython 3.12-3.14 (manylinux and musllinux),
# plus pure-Python wheels. That is CI (ubuntu-latest) and the container image (python:3.14-slim,
# Debian bookworm, glibc 2.36). It is deliberately NOT a cross-platform lock file: for local work
# on macOS or Windows use the checked-in virtualenv (see README.md) rather than this file. No
# sdists are listed, so a platform without a matching wheel fails loudly instead of building a
# subtly different binary.
#
# REGENERATING
# ------------
# Hashes come from PyPI's per-release JSON API (`https://pypi.org/pypi/<name>/<version>/json`,
# field `urls[].digests.sha256`), which is the same value pip verifies after download.
